# 引导学习评估

本目录提供 16 个设计用例，用于检查数学正确性、资料引用、提示节奏、迁移任务和学习记录。**目前所有案例均为 `not_run`，尚未在任何平台或模型执行。** 案例数量不等于通过数量，也不代表真实学生学习效果。

- [用例与评阅标准](learning_cases.json)：含学生输入、环境夹具、预期行为、失败信号和数学参考结论，供测试人员使用。
- [无等长标记的三角形夹具](fixtures/triangle_without_marks.svg)：供第 3 项图像测试使用。
- [学生演示任务](../examples/STUDENT_TASKS.md)：可供首次体验使用，未附参考答案。
- [数学参考解](../examples/DEMO_PACK.md)：供 AI 备课与评阅核对。

## 使用范围

普通数学题与模拟学生输入为本项目编写。涉及原知识库记录的测试只提供 ID 和状态字段，用于检查系统是否如实说明来源、缺口和核验状态；这些用例不要求公开原题全文。

本套件检验原型行为。它不能单独证明学习成绩提升、长期掌握或适合所有学生。长期学习效果需要另行设计试用与延迟复查。

## 手工执行步骤

### 1 固定本次环境

记录测试日期、平台、模型与可确认的版本、所用提示词版本、可访问文件、工具权限和知识库版本。获取不到模型具体版本时记“未提供”，不能自行猜测。

每个用例使用新会话。将基础引导指令保持相同；如果平台支持系统指令，可放在那里，否则作为第一条设置消息发送并记录这一方式。可采用如下基线：

> 你是初中数学学习伙伴。结合本次实际可读的资料和学生目标，准确解释概念与条件。只引用真正读到的材料，说明资料缺口和核验状态。自查时先让学生作答；卡住时给适量提示，必要时直接解释或示范，再让学生继续。每次聚焦一个关键任务，接受合理的不同解法。结束时区分独立完成、帮助后完成和尚未检查，不从一次回答推断长期掌握。

这是拟用的测试指令，不是已经验证的最佳提示词。改动指令后记录新版本，避免把不同设置下的结果混在一起。

### 2 准备用例夹具

打开 `learning_cases.json`，一次选择一个用例。`setup` 指定需要提供的题目环境、既有对话、检索记录或工具限制。只向被测 AI 提供完成该用例所需的可见材料。

`expected_behavior`、`failure_signals`、`mathematical_oracle` 和本页的评阅说明属于测试人员资料，不能放入被测 AI 的上下文。否则答案或通过条件已被提前泄露，不能再作为独立测试结果。

第 6 项使用“没有写入、持久记忆和提醒能力”的测试条件。如果实际环境无法按该条件配置，应注明差异并记 `blocked`，或另建不同条件的新用例；不能忽略设置差异照抄结果。

### 3 实际发送图像

第 3 项使用 `fixtures/triangle_without_marks.svg`。先在浏览器或图像工具中打开 SVG，或将其转换为 PNG，再作为真正的图片输入发送。图中只有三角形边界及 A、B、C 标注，没有等长、角度或平行标记。

visible_marks、not_present 和其他图像夹具元数据只供评阅者准备材料，不能作为文字发送给被测 AI；该例的被测输入只包含实际图片与学生问题。

仅把路径或“图中没有等长标记”这句话发送给 AI，不算执行该图像用例。平台或当前模型不能接收图片时，结果记 `blocked`，写明缺少图像输入能力；不能据文字回答记为通过。

### 4 逐轮发送学生输入

按 `student_turns` 顺序发送，等待每轮输出后才发送下一轮。`setup.conversation_history` 是用例开始前的固定历史；可以作为明确标注的已有对话提供，后续学生答案不能提前提供。

保留 AI 完整回复。若系统前一轮已经违反关键要求，使后续任务无法正常衔接，记录该处失败并停止该例；不修改学生答案来帮助系统通过。学生明确要求讲解的用例，评阅的是能否适当调整支持，不能把持续追问自动评成更好。

### 5 根据证据记录结果

先检查数学、条件和引用，再看引导过程。用例中的数学结论是参考判定；成立的其他方法也可以通过。评阅应写明发生在第几轮、哪句话或哪一步，而不是只填主观感受。

每次运行另存一份结果，不覆盖本套件的设计基线。可以使用以下记录格式；这里仍是未执行模板：

```json
{
  "case_id": "MATH-EVAL-01",
  "status": "not_run",
  "run_at": null,
  "platform": null,
  "model_version": null,
  "prompt_version": null,
  "dataset_version": null,
  "tool_permissions": null,
  "turn_outputs": [],
  "blocking_reason": null,
  "critical_failure": null,
  "dimension_scores": {},
  "reviewer": null,
  "rationale": null
}
```

## 结果状态

| 状态 | 含义 |
|---|---|
| `not_run` | 尚未按规定输入并观察该例 |
| `blocked` | 缺少图像输入、指定资料或所需环境条件，无法按原定义执行；需要写明原因 |
| `pass` | 已执行，必要行为有可检查证据，未出现失败信号 |
| `fail` | 已执行，出现数学、证据或目标行为错误；需要记录具体位置与原因 |

`blocked` 只记录环境阻碍。模型在具备条件时不完成任务、编造来源或给错结论，属于待判定的失败，不能用 `blocked` 隐去问题。

## 评阅维度

| 维度 | 检查内容 |
|---|---|
| 数学与成立条件 | 运算、定义、定义域、分类完备性、取等条件正确 |
| 来源与核验状态 | 实际读过才引用；缺题干、缺答案和 AI 推断如实说明 |
| 模式与提示节奏 | 自查先作答；需要解释时能讲清；不无限追问 |
| 学生实质参与 | 学生完成计算、理由、判断或转化，参与不止于复述名称 |
| 迁移任务的独立性 | 新题先作答，前一轮提示和后一轮表现分别记录 |
| 过程记录 | 分清独立、帮助后和未检查；不虚称保存、提醒或长期掌握 |

过程维度可用 0、1、2：0 为违反要求，1 为部分满足，2 为清楚满足。没有观察到时用 `not_observed`，不能填 2。数学结论错误、编造来源或把未核题当标准练习，应标记关键失败，不能用其他过程分数抵消。

## 如何汇总

分别报告 `pass`、`fail`、`blocked`、`not_run` 数量，总和应等于本次选择的用例数。若计算执行通过率，使用 `pass / (pass + fail)`，同时保留阻塞和未运行数量；分母为零时写“尚无可计算结果”。

不同模型或配置做对比时，固定用例、可见资料、工具和判定标准，再分别报告结果。不要把部分用例的通过率写成整个项目的覆盖率，也不要将模型回答评估转换成学生学习效果结论。
