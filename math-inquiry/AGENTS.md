# 项目协作指令

本仓库用于初中数学知识框架与 AI 引导式学习实践。先读 README 和当前任务涉及的文档，明确用户是在学习数学，还是要求开发、审核或修改项目。只执行当前任务所需操作。

## 学习任务

- 学生求助、复习、预习和数学思维讨论以读取资料和对话为主，不修改知识库、脚本或原始材料。用户明确要求生成学习记录时，可以按其要求另存记录，区分独立完成、提示后完成和未检查。
- 先确认题目、条件、已有尝试和当前目标；图形外观不是已知条件。看不清的文字或标记要指出具体缺口。
- 只引用实际读到的资料。自拟演示标为自拟，AI 补充解释与教材内容分开。缺少资料、页码或版本证据时说明实际限制，不补造出处。
- 每次围绕一个关键任务推进。学生卡住时给必要提示；提示无效或学生要求直接讲解时，示范关键一步或给出必要完整说明，再邀请其继续。正式定义可以准确直接说明。
- 独立自查首轮保留答案，不在学生作答前展示会泄露解法的公式、例题答案或参考说明。学生完成后再核对。
- 检查适用条件、定义域、漏解、分类完整性和取等条件；接受成立的不同方法。例子和图像观察不能代替一般证明。
- 不把“懂了”、一次答对或模仿示范记录为长期掌握。要检验迁移，应使用未讲过的新任务。
- 家长方案尚未整合，不能把当前通用建议描述为已收到的原方案。

## 开发与内容维护

- 保留原始输入，在工作副本或明确输出位置生成结果。不要用旧版构建脚本直接覆盖包含中考层的数据库；先阅读 `docs/CURRENT_BASELINE.md`。
- 保持既有 `knowledge_id`、`example_id`、`relation_id` 和来源身份稳定。展示排序调整不能改变持久 ID；不同教材版本保留独立版本与页码映射。
- 修改资料来源、数学结论或审核状态时，写明对应记录、依据与变更原因。`verified` 是具体审核状态，不能因为通过结构测试而批量赋值。
- 区分研究数据包、当前文档草稿与未来公开导出；公开介绍的数量应来自对应产物实际统计。
- 公开产物以明确的文件及字段清单为依据。第三方原文、页图和解析可能存在于 JSONL、Markdown、curation 与数据库 payload，多种副本应一并检查；不把删除一个目录当作完成导出。
- 来源路径使用相对位置或本地配置；不要将作者电脑绝对路径、账号配置或真实学生个人信息写入公开示例。
- 文本统一使用 UTF-8；导入 ZIP 时检查路径安全、编码和重名冲突。编码恢复结果写入导入记录，不静默覆盖原包。
- 候选许可见 `LICENSE_POLICY.md`。不要把候选方案写成已生效授权，也不要替第三方材料改授许可或编造权利人。

## 验证与报告

- 只运行能检查本次实际风险的验证。查询修复应复跑相关示例并确认输入未变；构建修改应在隔离输出核对表、视图、引用和状态；公开导出应检查所有内容副本与链接。
- 数学审核、文件结构验证、平台实际运行、模拟对话和学生使用结果分别报告。未执行的检查写明未执行，不生成虚假的通过徽章或效果数字。
- 学习测试设计见 `evals/README.md`。记录输入、实际回答、观察结果和必要修正；没有真实运行记录时只称测试设计。
- 完成时说明修改内容、验证方式、实际结果和剩余问题。文档描述须与已经存在且能复现的功能一致。
