# 许可候选与公开材料范围

本文件记录拟公开仓库的许可设计。**当前仅为候选方案，没有替项目发起人签发正式许可证，也没有对现有研究包的全部材料作出再分发授权。** 本草稿未创建正式 `LICENSE` 文件或填写未经核实的权利人。

## 1 候选方案

| 内容范围 | 候选许可 | 正式发布前需要落实 |
|---|---|---|
| 项目原创代码及有权分发的代码改动 | MIT | 核对代码来源与现有通知，填写准确权利人，保留适用许可文本 |
| 项目原创说明、提示词、自拟任务、模拟对话、原创演示数据和文档图形 | CC BY 4.0 | 核对原创/改编来源，明确适用文件、署名方式和修改记录 |
| 教材、试卷、原页图、外部答案解析及其转录 | 各材料已有许可或其他明确公开依据 | 逐项确认适用范围，不能直接套用上面两项 |

具体路径、字段及排除项见[发布决策](docs/release-decisions.md)。当前 README 横幅是项目文档的装饰示意，不是教材图或真实知识图谱统计。

MIT 候选方案允许按其条款使用和修改代码，并要求保留相应版权与许可通知，正式文本见 [MIT License](https://choosealicense.com/licenses/mit/)。CC BY 4.0 允许按其条件分享和改编材料，包括商业用途，要求适当署名、链接许可并说明修改，见 [CC BY 4.0 官方说明](https://creativecommons.org/licenses/by/4.0/deed.en)。

如果项目目标不包含商业复用，就需要重新选择内容许可；不能采用 CC BY 4.0 后再用 README 中的一句话增加相反限制。许可如何在仓库中呈现，可参考 [GitHub 许可说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)。

## 2 研究资料如何进入公开项目

先记录材料来源和公开依据，再确定进入公开产物的文件与字段。来源记录至少包含：材料或记录 ID、内容类别、出处、权利人或授权来源、适用许可、公开范围以及判断依据。

- 明确可公开的原创说明、提示词和演示，可以进入文档与示例目录。
- 外部教材和试卷按各自范围处理；未明确进入公开范围的材料保留为本地输入。
- 元数据中若包含题干、解法、段落证据或完整 payload，也需按实际内容判断。把内容装进 JSON 或 SQLite 不改变其来源。
- 原电脑绝对路径、缓存和账号配置不属于公开学习材料，使用相对位置或本地配置。
- 学生体验示例优先采用自拟内容；实际使用记录的公开范围需要单独落实，不能由项目代码许可自动覆盖。

`verified`、文件摘要或可追溯页码描述内容审核与定位，不代表材料已经取得某种公开许可。

## 3 正式许可落地时的步骤

1. 确认代码、原创内容和第三方材料各自的权利归属与分发范围。
2. 采用最终决定的标准许可文本，填写真实权利人；将代码许可与原创内容许可的适用文件说明清楚。
3. 保留第三方既有通知和必要署名，单列不适用项目许可的材料。
4. 由明确选定的公开记录生成数据库和 Markdown，检查不同副本中是否仍含排除内容。
5. 更新 README 中的许可与功能状态，再把发布目录作为新用户的输入验证一次。

正式发布前，“研究数据规模”“草稿内容”“实际公开文件”应分别说明。当前候选方案不能被引用为已完成授权的凭据。
