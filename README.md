Math Inquiry｜数学思考伙伴
以数学知识框架为基础，让孩子在与 AI 的交流中理解概念、解释方法、建立联系，并尝试独立解决问题。
Math Inquiry 是一个面向初中数学的 AI 引导式学习项目，也是一次围绕真实学习需求开展的 FDE 实践。项目从教材中的基础概念、例题、习题与案例出发，通过资料选择、知识整理和学习流程设计，探索怎样让 AI 更有依据、更有步骤地参与数学学习。
当前以初中数学为起点，后续逐步扩展数学思想体系、教材版本和高中内容。
为什么做这个项目
数学学习中，有一些值得继续追问的问题：
- 记住了一个公式，能不能解释它为什么成立？
- 看懂了一道例题，能不能说明为什么选择这种方法？
- 题目换了一个条件，原来的思路是否仍然适用？
- 做错一道题时，困难究竟出在概念、条件、方法还是计算？
- 学过的知识之间，能不能建立可以用于解题的联系？
这个项目希望把这些问题放进日常学习过程。
学生带着题目、已有尝试和具体疑问进入对话。AI 根据实际读取的知识资料，提供必要的解释、提示和示范；学生参与计算、判断、表达与修正，再通过新的任务检查自己能独立做到什么。
项目关注的学习结果包括：能说清概念的含义，能检查方法的适用条件，能解释关键步骤的依据，也能在条件变化时重新判断。
核心思路
项目将三个部分组织在一起：数学知识框架、引导式学习流程、可检查的学习过程。
数学知识框架
围绕一个知识点，整理它的定义、成立条件、前置知识、相关例题、常见误区和与其他知识的联系。
例如，学习分式约分时，除了完成代数变形，还需要理解原分母不能为零，以及化简为什么必须保留原式的取值限制。
知识之间的联系也需要有理由：为什么某个概念适合作为准备知识？为什么一道题可以帮助理解某种方法？哪些联系来自教材，哪些属于项目的教学整理？
引导式学习流程
根据学生当前的任务选择合适的起点，围绕一个关键问题逐步推进。
需要时直接解释概念或示范关键一步，然后邀请学生继续。学生可以通过计算、画图、说明理由、比较方法、寻找反例等方式参与，而不是只回答“懂了没有”。
可检查的学习过程
保留学生的第一次尝试，记录提示发生的位置，区分独立完成、提示后完成和尚未检查的内容。
需要检验理解时，再给一道未讲过的新题或一个条件变化任务。对学习情况的判断应来自实际表现，并保留后续复查的空间。

一次学习可以怎样开始
下面是一段自拟的交互示例，用于说明项目的引导方式。
学生：
我在实数范围内解 x² = 4x。
两边除以 x，得到 x = 4。
我不确定是否漏了解，请先帮我检查这一步。
AI 可以先这样引导：
两边同除以 x，需要 x 满足什么条件？
先把 x = 0 代回原方程，看看会发生什么。
接下来，由学生完成这个检验，补充原来的解题过程，并解释为什么需要处理不同情况。如果学生仍然卡住，AI 可以示范关键一步，再让学生继续。
原题完成后，可以换一道相近的新题，观察学生是否会主动检查条件。学习记录应写清楚：哪些判断是独立完成的，哪些是在提示后补上的。
这个过程把方程计算、除法条件、分类讨论和解的完整性联系在了一起。

数学思想怎样进入知识框架
项目希望逐步把数学思想整理成学生能够理解、能够尝试使用的内容。
例如：
- 转化： 把当前问题变成熟悉或更容易处理的形式。
- 分类讨论： 找到影响结论的条件，检查不同情况是否被完整覆盖。
- 数形结合： 在数量关系与图形表示之间建立联系。
- 函数与方程： 根据问题目标，理解变量关系与特定取值之间的联系。
- 反例与条件检验： 用具体检验发现猜想的限制，再重新表述结论。
每一类思想都应结合具体任务说明：
1. 看到什么信息时，可以考虑这个思路？
2. 哪一步实际体现了它？
3. 为什么这一步有效？
4. 使用前需要检查什么条件？
5. 改变条件后，原思路需要怎样调整？
现有具体方法与题目标签为这一层提供了基础。后续将先完善少量完整的思想卡，再逐步扩展经过审校的关联。
如何开始体验
项目面向能够读取工作区文件或接收上传资料的 AI 环境，计划持续完善在 Codex、WorkBuddy 等平台上的使用路径。
建议从一个小范围开始：
1. 提供本次需要的知识资料与对应场景提示词。
2. 先让 AI 说明实际读取了哪些文件、条目和条件，自己核对出处。
3. 提供题目、已有尝试和当前疑问。
4. 完成一个具体任务，再根据需要请求提示或示范。
5. 结束时保存学习记录，需要时换一道新题独立尝试。
第一次体验可以使用项目自拟材料，不需要先准备完整教材。各平台的文件读取、图像输入和工具执行能力，应在实际环境中核对；平台使用指南与现场验证结果分别记录。

如何判断项目是否在进步
项目分别记录三类证据：
工程证据： 数据是否一致，引用是否有效，查询和构建是否能按说明完成。
内容证据： 数学结论、适用条件、分类、取等条件与来源是否准确。
交互证据： 学生是否有实质参与，提示是否适量，是否能在新的任务中独立尝试。
当前已设计 16 项学习评估案例，覆盖漏解、分式取值限制、题图条件不足、资料缺失、未核题目、不同正确解法与学习记录等情况。用例设计与实际运行结果分开保存；目前这组案例尚未完成平台模型测试。
真实学生的学习效果，需要结合实际使用过程与后续复查继续研究。模拟对话用于说明交互方式。
适合谁参与
- 学生： 从具体问题开始，练习解释概念、检查条件和表达思路。
- 家长： 协助准备资料，观察孩子怎样尝试、获得帮助和修正。
- 教师： 审校知识内容，完善追问、例题与数学思想之间的联系。
- 开发者与研究者： 研究数据组织、检索、交互设计和评估方法，改进项目的可用性。

参与贡献

- 修正一个概念、条件或推导。
- 补充一个恰当的例子、反例或变式。
- 为题目与方法的联系提供清楚理由。
- 提交一段可复现的学习对话问题。
